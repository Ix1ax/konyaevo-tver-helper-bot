# Telegram-бот для просмотра расписания занятий и замен Тверского колледжа им. А.Н. Коняева.

Данные загружаются напрямую из Google Таблиц колледжа и периодически обновляются в фоне. Интерфейс построен на inline-кнопках через редактирование одного сообщения, чтобы не засорять историю чата.

## Функционал

- **Telegram Mini App (Web App):**
  - Минималистичный интерфейс с полупрозрачными поверхностями Liquid Glass
  - Сводка дня *"Начнёшь в X · закончишь в Y · N пар"*
  - Просмотр свободных и занятых аудиторий по слотам (пары 1..6)
  - Поиск преподавателей с алфавитным фильтром и полным расписанием
  - Светлая и тёмная темы с едиными контурными иконками Lucide
  - Сохранение выбора профиля и темы; явное сообщение при недоступности данных
  - Поддержка нативной вибрации (Haptic Feedback)

- **Для студентов (в чате):**
  - Сохранение выбранного курса и группы
  - Расписание на сегодня, завтра и на всю неделю
  - Просмотр ежедневных замен
  - Определение типа недели (красная / синяя)

- **Для преподавателей (в чате):**
  - Поиск преподавателя по алфавитному рубрикатору
  - Расписание занятий с указанием групп и аудиторий
  - Просмотр замен и автоматический учёт отмен (если пару заменили)

## Стек

- **Бэкенд:** Java 17, Spring Boot 3 (REST API + Telegram Long Polling Bot), H2 Database, Apache POI
- **Фронтенд (Mini App):** React 18, Vite, TypeScript, Tailwind CSS, Lucide Icons, Telegram WebApp SDK
- **Хостинг Mini App:** Cloudflare Pages Functions (бесплатный HTTPS прокси к API)

## Настройка и запуск

### 1. Переменные окружения

Скопируйте пример файла окружения:

```bash
cp .env.example .env
```

Параметры в `.env`:
- `BOT_TOKEN` — токен бота от @BotFather (обязательно)
- `BOT_USERNAME` — юзернейм бота
- `BOT_BASE_URL` — базовый URL Telegram Bot API (опционально, по умолчанию `https://api.telegram.org/bot`. Указывается при работе через Cloudflare Worker или reverse proxy)
- `DB_URL` — строка подключения к базе H2 (по умолчанию `jdbc:h2:file:./data/konyaevo-bot`)
- `DB_PASSWORD` — пароль к БД (если задан)

### 2. Сборка

```bash
./mvnw clean package -DskipTests
```

Собранный JAR появится в `target/konyaevo-bot-1.3.0.jar`.

### 3. Запуск

Linux / macOS:
```bash
chmod +x start.sh
./start.sh
```

Windows:
```cmd
start.bat
```

Либо напрямую через Java:
```bash
java -jar target/konyaevo-bot-1.3.0.jar
```

## 📱 Telegram Mini App (Web App)

Фронтенд расположен в папке `frontend/` в рамках единого монорепозитория.

### Локальная разработка Mini App:
```bash
cd frontend
npm install
npm run dev
```
Приложение откроется на `http://localhost:5173`. Запросы к `/api` автоматически проксируются на запущенный Spring Boot бэкенд (`http://127.0.0.1:8080`).

### Деплой на Cloudflare Pages (Бесплатный HTTPS + Авто-прокси):
1. Зайдите в [Cloudflare Dashboard](https://dash.cloudflare.com/) → **Workers & Pages** → **Create application** → **Pages** → **Connect to Git**.
2. Выберите ваш GitHub репозиторий `konyaevo-tver-help`.
3. Настройки сборки (Build settings):
   - **Framework preset**: `Vite`
   - **Root directory**: `frontend`
   - **Build command**: `npm run build`
   - **Build output directory**: `dist`
4. В разделе **Environment variables** добавьте переменную:
   - `BACKEND_URL`: `http://IP_ВАШЕГО_СЕРВЕРА:8080` (адрес вашего сервера с ботом)
5. Нажмите **Save and Deploy**.
6. Cloudflare выдаст ссылку вида `https://konyaevo-tver-help.pages.dev` с бесплатным HTTPS. Cloudflare Pages Functions (`frontend/functions/api/[[path]].ts`) будет автоматически и безопасно проксировать все запросы к вашему бэкенду без необходимости настраивать SSL-сертификаты на сервере!

### Подключение Mini App к Telegram боту:
В файле `.env` на сервере укажите полученный URL:
```bash
MINI_APP_URL=https://konyaevo-tver-help.pages.dev
```
И перезапустите бота. В главном меню бота появится кнопка **«📱 Открыть Mini App»**!
Также можно привязать Web App к постоянной кнопке меню через @BotFather: команда `/setmenubutton`.

## Панель администратора в Mini App

Профиль администратора содержит статистику пользователей бота, студентов,
преподавателей, уведомлений и ненастроенных профилей, а также сводку расписания
и замен. Это статистика записей в БД бота, а не число посещений Mini App.

Доступ к `/api/admin/overview` проверяется сервером: подпись `Telegram.WebApp.initData`,
время запуска приложения (не старше часа) и права через `AdminService`.
Без запуска через Telegram административный блок скрыт. Идентификатор из
`initDataUnsafe` не используется для выдачи прав. Проверка подписи следует
[документации Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).

Адрес API задаётся при сборке (`VITE_API_URL`), в профиле настройки сервера нет.
Для GitHub Pages задайте переменную репозитория `VITE_API_URL` с HTTPS-адресом
бэкенда (например, `https://api.example.ru/api`). Workflow передаёт её в сборку.
GitHub Pages не проксирует `/api` и не запускает Java-бэкенд. При обновлении
нужно развернуть и frontend, и новый JAR.

## Проверки и устройство кода

```bash
./mvnw package
npm run build --prefix frontend
```

`ScheduleResolver` собирает пары с заменами для REST API и сообщений бота.
`AcademicWeek` рассчитывает цвет недели. `TelegramMiniAppAuth` проверяет данные
запуска Mini App, `AdminApiController` выдаёт административную сводку.
Фронтенд использует общие `ScheduleDay`, `LessonCard`, `IconBadge` и стили в
`frontend/src/styles/index.css`. Все контурные иконки имеют размер 20 px.

[Отчёт аудита](docs/audit/REPORT.md) содержит результаты и границы проверки.


## Уведомления, отзывы и медиа

Профиль Mini App сохраняется в базе чат-бота через подписанные данные Telegram.
Уведомления о заменах и расписании на завтра используют общее время по Москве
и выбранные дни недели. В браузере вне Telegram расписание доступно, а для
сохранения уведомлений нужно открыть Mini App через Telegram.

Администратору доступны активность за сутки, неделю и месяц, общий список замен,
средняя оценка приложения и отзывы с пагинацией. Общие замены и отзывы защищены
на сервере; изменение роли в профиле не даёт прав администратора.

Оценка появляется через минуту видимого использования Mini App в нижнем попапе.
Окно можно закрыть до следующего запуска. Голос можно оставить один раз;
для 1–4 звёзд обязателен комментарий. Отзывы хранятся в базе бэкенда.

Для медиа-рассылки отправьте `/broadcast`, затем прикрепите одно видео, фото,
GIF или документ с подписью. Другой вариант: ответьте `/broadcast` на готовое
сообщение с медиа. Бот покажет предпросмотр и попросит подтвердить отправку.
`/cancel` отменяет ожидание файла. Текстовый вариант `/broadcast текст` сохранён.
Файлы не скачиваются на сервер: бот повторно использует Telegram `file_id`.

`BOT_MAX_THREADS` управляет параллельной обработкой чатов (по умолчанию 16,
допустимое число обработчиков 4–64). Действия одного чата выполняются по порядку,
очереди ограничены, статистика активности кешируется. Данные регистрации
старых пользователей неизвестны, поэтому счётчик новых пользователей начинает
корректно накапливаться после обновления.

В профиле приложения доступна «Помощь», в боте — команда `/help` и кнопка меню. Справка администратора дополнительно описывает статистику, обновление данных и медиа-рассылки. Проверка календарных дат и кеша фронтенда: `npm run test:helpers --prefix frontend`.


## Обновление до 2.0.0 через systemd

Бэкенд использует порт `8090` по умолчанию. В существующем `.env` или
EnvironmentFile сервиса явно задайте `SERVER_PORT=8090`: старое значение
переменной имеет приоритет над новым значением по умолчанию. В Nginx направьте
HTTPS-запросы API на `http://127.0.0.1:8090`. Сохраните действующий токен,
`DB_URL`, пароль базы и рабочий каталог сервиса.

До обновления проверьте `systemctl cat konyaevo-bot.service` и чистоту рабочего
дерева на сервере. Соберите релиз командой `./mvnw clean package` при работающем
старом боте. Если сервис запускает JAR непосредственно из `target`, собирайте
в отдельном каталоге: команда `clean` удаляет содержимое `target`.

Для замены остановите сервис, сохраните прежний JAR, конфигурацию и каталог
`data` (файловую H2 копируйте только после остановки). Установите новый
`konyaevo-bot-2.0.0.jar` в путь, указанный в ExecStart, либо обновите этот путь.
После изменения unit-файла выполните `systemctl daemon-reload`, затем запустите
сервис. Проверьте журнал и `curl --fail http://127.0.0.1:8090/api/info`.
Не запускайте локальную копию с тем же реальным токеном одновременно с сервером.

При откате остановите сервис и восстановите прежние JAR, конфигурацию и
сохранённую базу вместе: новая версия расширяет схему H2. Тег релиза — `v2.0.0`.
