# Telegram-бот для просмотра расписания занятий и замен Тверского колледжа им. А.Н. Коняева.

Данные загружаются напрямую из Google Таблиц колледжа и периодически обновляются в фоне. Интерфейс построен на inline-кнопках через редактирование одного сообщения, чтобы не засорять историю чата.

## Функционал

- **Telegram Mini App (Web App):**
  - Минималистичный интерфейс с полупрозрачными поверхностями Liquid Glass
  - Сводка дня *"Начнёшь в X · закончишь в Y · N пар"*
  - Просмотр свободных и занятых аудиторий по слотам (пары 1..6)
  - Поиск преподавателей с алфавитным фильтром и полным расписанием
  - Светлая и тёмная темы с едиными контурными иконками Lucide
  - Сохранение выбора профиля и темы; явное сообщение при недоступности данных
  - Поддержка нативной вибрации (Haptic Feedback)
  - Маскот Парыч: подсказка над расписанием («через 12 мин — каб. 305»), спящий Парыч в выходные и на загрузке
  - Огонёк учебных дней, заморозки, ежедневные задания, уровни, облики и награды
  - Работа при недоступном сервере: резервный адрес API и копия расписания на GitHub Pages

- **Для студентов (в чате):**
  - Сохранение выбранного курса и группы
  - Расписание на сегодня, завтра и на всю неделю
  - Просмотр ежедневных замен
  - Определение типа недели (красная / синяя)
  - Напоминание в 21:00, если огонёк вот-вот погаснет (можно отключить)

- **Для преподавателей (в чате):**
  - Поиск преподавателя по алфавитному рубрикатору
  - Расписание занятий с указанием групп и аудиторий
  - Просмотр замен и автоматический учёт отмен (если пару заменили)

## Стек

- **Бэкенд:** Java 17, Spring Boot 3 (REST API + Telegram Long Polling Bot), H2 Database, Apache POI
- **Фронтенд (Mini App):** React 18, Vite, TypeScript, Tailwind CSS, Lucide Icons, Telegram WebApp SDK
- **Хостинг Mini App:** Cloudflare Pages Functions (бесплатный HTTPS прокси к API)

## Настройка и запуск

### 1. Переменные окружения

Скопируйте пример файла окружения:

```bash
cp .env.example .env
```

Параметры в `.env`:
- `BOT_TOKEN` — токен бота от @BotFather (обязательно)
- `BOT_USERNAME` — юзернейм бота
- `BOT_BASE_URL`, `BOT_PROXY_*` — основной маршрут до Telegram Bot API (по умолчанию `https://api.telegram.org/bot` без прокси)
- `BOT_FALLBACK_BASE_URL`, `BOT_FALLBACK_PROXY_*` — запасной маршрут (см. «Маршруты до Telegram и VPN»)
- `VPN_URL` — ссылка `vless://` для локального xray, в одинарных кавычках
- `DB_URL` — строка подключения к базе H2 (по умолчанию `jdbc:h2:file:./data/konyaevo-bot`)
- `DB_PASSWORD` — пароль к БД (если задан)

### 2. Сборка

```bash
./mvnw clean package -DskipTests
```

Собранный JAR появится в `target/konyaevo-bot-2.2.1.jar`.

### 3. Запуск

Linux / macOS:
```bash
chmod +x start.sh
./start.sh
```

Windows:
```cmd
start.bat
```

Либо напрямую через Java:
```bash
java -jar target/konyaevo-bot-2.2.1.jar
```

## 📱 Telegram Mini App (Web App)

Фронтенд расположен в папке `frontend/` в рамках единого монорепозитория.

### Локальная разработка Mini App:
```bash
cd frontend
npm install
npm run dev
```
Приложение откроется на `http://localhost:5173`. Запросы к `/api` автоматически проксируются на запущенный Spring Boot бэкенд (`http://127.0.0.1:8080`).

### Деплой на Cloudflare Pages (Бесплатный HTTPS + Авто-прокси):
1. Зайдите в [Cloudflare Dashboard](https://dash.cloudflare.com/) → **Workers & Pages** → **Create application** → **Pages** → **Connect to Git**.
2. Выберите ваш GitHub репозиторий `konyaevo-tver-help`.
3. Настройки сборки (Build settings):
   - **Framework preset**: `Vite`
   - **Root directory**: `frontend`
   - **Build command**: `npm run build`
   - **Build output directory**: `dist`
4. В разделе **Environment variables** добавьте переменную:
   - `BACKEND_URL`: `http://IP_ВАШЕГО_СЕРВЕРА:8080` (адрес вашего сервера с ботом)
5. Нажмите **Save and Deploy**.
6. Cloudflare выдаст ссылку вида `https://konyaevo-tver-help.pages.dev` с бесплатным HTTPS. Cloudflare Pages Functions (`frontend/functions/api/[[path]].ts`) будет автоматически и безопасно проксировать все запросы к вашему бэкенду без необходимости настраивать SSL-сертификаты на сервере!

### Подключение Mini App к Telegram боту:
В файле `.env` на сервере укажите полученный URL:
```bash
MINI_APP_URL=https://konyaevo-tver-help.pages.dev
```
И перезапустите бота. В главном меню бота появится кнопка **«📱 Открыть Mini App»**!
Также можно привязать Web App к постоянной кнопке меню через @BotFather: команда `/setmenubutton`.

## Панель администратора в Mini App

Профиль администратора содержит статистику пользователей бота, студентов,
преподавателей, уведомлений и ненастроенных профилей, а также сводку расписания
и замен. Это статистика записей в БД бота, а не число посещений Mini App.

Доступ к `/api/admin/overview` проверяется сервером: подпись `Telegram.WebApp.initData`,
время запуска приложения (не старше часа) и права через `AdminService`.
Без запуска через Telegram административный блок скрыт. Идентификатор из
`initDataUnsafe` не используется для выдачи прав. Проверка подписи следует
[документации Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).

Адрес API задаётся при сборке (`VITE_API_URL`), в профиле настройки сервера нет.
Для GitHub Pages задайте переменную репозитория `VITE_API_URL` с HTTPS-адресом
бэкенда (например, `https://api.example.ru/api`). Workflow передаёт её в сборку.
Необязательная `VITE_API_FALLBACK_URL` задаёт резервный адрес (см. раздел
«Доступность Mini App»).
GitHub Pages не проксирует `/api` и не запускает Java-бэкенд. При обновлении
нужно развернуть и frontend, и новый JAR.

## Уведомления, отзывы и медиа

Профиль Mini App сохраняется в базе чат-бота через подписанные данные Telegram.
Уведомления о заменах и расписании на завтра используют общее время по Москве
и выбранные дни недели. В браузере вне Telegram расписание доступно, а для
сохранения уведомлений нужно открыть Mini App через Telegram.

Администратору доступны активность за сутки, неделю и месяц, общий список замен,
средняя оценка приложения и отзывы с пагинацией. Общие замены и отзывы защищены
на сервере; изменение роли в профиле не даёт прав администратора.

Оценка появляется через минуту видимого использования Mini App в нижнем попапе.
Окно можно закрыть до следующего запуска. Голос можно оставить один раз;
для 1–4 звёзд обязателен комментарий. Отзывы хранятся в базе бэкенда.

Для медиа-рассылки отправьте `/broadcast`, затем прикрепите одно видео, фото,
GIF или документ с подписью. Другой вариант: ответьте `/broadcast` на готовое
сообщение с медиа. Бот покажет предпросмотр и попросит подтвердить отправку.
`/cancel` отменяет ожидание файла. Текстовый вариант `/broadcast текст` сохранён.
Файлы не скачиваются на сервер: бот повторно использует Telegram `file_id`.

`BOT_MAX_THREADS` управляет параллельной обработкой чатов (по умолчанию 16,
допустимое число обработчиков 4–64). Действия одного чата выполняются по порядку,
очереди ограничены, статистика активности кешируется. Данные регистрации
старых пользователей неизвестны, поэтому счётчик новых пользователей начинает
корректно накапливаться после обновления.

В профиле приложения доступна «Помощь», в боте — команда `/help` и кнопка меню. Справка администратора дополнительно описывает статистику, обновление данных и медиа-рассылки. Проверка календарных дат и кеша фронтенда: `npm run test:helpers --prefix frontend`.


## Парыч и огонёк

Парыч — маскот Mini App, нарисованный в SVG (`frontend/src/components/Mascot.tsx`).
Он живёт в центре нижней панели (`BottomNav`): кнопка показывает облик и огонёк,
серый значок с оранжевым кольцом — сегодняшний учебный день ещё не засчитан.
Вкладок пять: «Расписание» (внутри переключатель «Сегодня / Завтра»), «Неделя»,
Парыч, «Поиск» («Преподаватели / Кабинеты») и «Профиль». Списки преподавателей
и аудиторий разбиты на страницы (`Pager`).
Подсказка над расписанием выбирается по московскому времени
(`frontend/src/utils/mascotTip.ts`): скоро пара, идёт пара, перерыв, пары
закончились; для «Завтра» — сводка дня. Замены отмечаются отдельно.

Огонёк считает учебные дни подряд, в которые пользователь открыл расписание
в Mini App или в боте (активность учитывает `UserActivityService`). Учебный
день — будний день, в который у группы или преподавателя есть пары по основному
расписанию. Выходные, дни без пар и каникулы (1 июля — 31 августа,
31 декабря — 8 января) серию не прерывают. Каждые 7 дней подряд дают заморозку
(не больше двух): она закрывает пропущенный учебный день.

Опыт начисляется раз в день за задания: открыть расписание (+10), заглянуть во
«Завтра» после 18:00 (+15), поделиться расписанием или сохранить его картинку (+20), а также +50 за каждые
7 дней огонька. Уровни 1–10 открывают облики Парыча. Логика — в `MascotService`,
прогресс хранится в таблице `mascot_progress`, API — `/api/mascot`
(подпись Telegram обязательна).

Напоминание приходит в боте в 21:00 по будням, только если серия не меньше
1 дня и пропуск сегодняшнего дня погасит огонёк. При серии 0 и после того,
как огонёк погас, бот не пишет. Отключается кнопкой «Не напоминать» или на
экране Парыча; при блокировке бота отключается автоматически.

## Поддержка Парыча звёздами

Пользователи могут поддержать проект звёздами Telegram (валюта `XTR`):
платёжный провайдер, токен и кошелёк не нужны, звёзды приходят на баланс бота
(виден в @BotFather). Логика — `DonationService`, платежи — таблица `donation`
(ключ — номер платежа Telegram, повторное уведомление не засчитывается).

- Mini App: плашка «Поддержать» в шапке дня, карточка под парами сегодня
  (скрывается на две недели, поддержавшим не показывается) и блок на экране
  Парыча. Счёт создаёт `POST /api/donate` (подпись Telegram обязательна) и
  открывает `Telegram.WebApp.openInvoice`.
- Бот: кнопка «⭐ Поддержать Парыча», `/donate` и ссылка
  `t.me/<бот>?start=donate`. Суммы 25, 50, 100, 250 или своя — от 1 до 10 000.
- За любую поддержку открывается облик «Звёздный», от 250 ⭐ всего — «Корона»;
  облик надевается сразу, в приложении показывается благодарность.
- `/paysupport` — справка по оплате, `/paysupport текст` пересылает вопрос
  администраторам. В `/stats` видно, сколько звёзд собрано и от скольких людей.

Главное меню бота: «Открыть приложение», «Сегодня / Завтра / Неделя»,
«Замены», «⚙️ Ещё» (уведомления, смена группы, преподавателя или роли, справка)
и «⭐ Поддержать Парыча».

## Доступность Mini App

В части мобильных сетей и при VPN, который направляет российские адреса мимо
туннеля, телефон не достаёт до сервера API, хотя страница и бот работают.
Поэтому клиент (`frontend/src/api/client.ts`) получает данные по цепочке:

1. Основной адрес `VITE_API_URL`.
2. Резервный адрес `VITE_API_FALLBACK_URL`, если задан. Клиент запоминает
   адрес, который ответил, и при ошибке сети делает ещё один круг.
3. Копия расписания на GitHub Pages (`./data/`). Если сервер не ответил за
   5 секунд, открытые данные берутся из копии, а сверху видно время копии.
   День недели и цвет недели пересчитываются на телефоне.
4. Если недоступно всё — экран с кнопками «Повторить» и «Расписание в чате».

Копию выгружает `frontend/scripts/snapshot.cjs` в шаге workflow при каждом
деплое и по расписанию каждые 30 минут. Если API во время сборки недоступен,
переносится прошлая опубликованная копия. Профиль, уведомления, огонёк и
отправка картинки работают только через сервер.

Резервный адрес — Cloudflare Worker из `deploy/cloudflare-worker`. Запросы `/api/*`
он пересылает на `BACKEND_URL` без изменений, поэтому подпись Telegram и CORS
проверяет сам бэкенд. Запросы `/bot*` уходят в `api.telegram.org`: этот же Worker
служит маршрутом до Telegram для бота.

```bash
cd deploy/cloudflare-worker
npx wrangler deploy
```

Затем добавьте переменную репозитория `VITE_API_FALLBACK_URL` с адресом
Worker (например, `https://konyaevo-api-proxy.<имя>.workers.dev`) или своим
поддоменом, привязанным к Worker в Cloudflare.

## Маршруты до Telegram и VPN

Бот ходит в Telegram Bot API одним из двух маршрутов (`TelegramRoutes`):

```
BOT_BASE_URL=https://konyaevo-tver-helper-bot.ixlax.workers.dev/bot
BOT_PROXY_TYPE=NO_PROXY
BOT_FALLBACK_PROXY_TYPE=SOCKS5
BOT_FALLBACK_PROXY_HOST=127.0.0.1
BOT_FALLBACK_PROXY_PORT=10808
```

Здесь основной маршрут — Cloudflare Worker, запасной — `api.telegram.org` через
локальный xray (адрес запасного маршрута по умолчанию `api.telegram.org`).
Без `BOT_FALLBACK_*` бот работает одним маршрутом, как раньше.

- Отправка сообщений переходит на запасной маршрут, только если до Telegram не
  удалось подключиться (отказ соединения, недоступный прокси, страница шлюза
  вместо ответа Telegram). Если Telegram ответил или соединение оборвалось после
  отправки, запрос не повторяется: сообщение не придёт дважды.
- Опрос обновлений (`TelegramPoller`) переключается при любой сетевой ошибке.
- Пока бот работает через запасной маршрут, каждые 5 минут проверяется основной;
  когда он отвечает, бот возвращается на него.
- ImageKit пробует прокси маршрутов в том же порядке.
- Опрос Telegram запускается в фоне после старта приложения. API и Mini App
  поднимаются сразу, даже если Telegram недоступен; бот подключится, как только
  ответит любой маршрут (повтор с паузой до 30 секунд).

Проверка: `GET /api/health` возвращает `{"api":"ok","telegram":"ok","route":"primary"}`
(`telegram: down`, если Telegram не отвечал больше 90 секунд; `route: fallback` —
работает запасной маршрут). Команда `/stats` у администратора показывает активный
маршрут. Переключения пишутся в журнал с меткой `[TELEGRAM ROUTE]`.

Локальный xray настраивается из ссылки VPN. Ссылку `vless://` (её можно
скопировать в Happ) положите в `.env` в одинарных кавычках — в ней есть `&` и `#`:

```
VPN_URL='vless://...'
```

Затем выполните из каталога бота от root:

```bash
./deploy/xray/set-vpn.sh
```

Скрипт собирает конфиг `/usr/local/etc/xray/config.json` (SOCKS5 `127.0.0.1:10808`,
HTTP `127.0.0.1:10809`), проверяет его через `xray run -test`, сохраняет прежний
конфиг рядом, перезапускает xray и проверяет доступ к Telegram. Если Telegram
через новый VPN недоступен, прежний конфиг возвращается. Ссылку можно передать
аргументом — скрипт запишет её в `.env`. `./deploy/xray/set-vpn.sh --check` только
проверяет текущий VPN. Перезапускать бота после смены VPN не нужно.

## Обновление до 2.0.0 через systemd

Бэкенд использует порт `8090` по умолчанию. В существующем `.env` или
EnvironmentFile сервиса явно задайте `SERVER_PORT=8090`: старое значение
переменной имеет приоритет над новым значением по умолчанию. В Nginx направьте
HTTPS-запросы API на `http://127.0.0.1:8090`. Сохраните действующий токен,
`DB_URL`, пароль базы и рабочий каталог сервиса.

До обновления проверьте `systemctl cat konyaevo-bot.service` и чистоту рабочего
дерева на сервере. Соберите релиз командой `./mvnw clean package` при работающем
старом боте. Если сервис запускает JAR непосредственно из `target`, собирайте
в отдельном каталоге: команда `clean` удаляет содержимое `target`.

Для замены остановите сервис, сохраните прежний JAR, конфигурацию и каталог
`data` (файловую H2 копируйте только после остановки). Установите новый
`konyaevo-bot-2.0.0.jar` в путь, указанный в ExecStart, либо обновите этот путь.
После изменения unit-файла выполните `systemctl daemon-reload`, затем запустите
сервис. Проверьте журнал и `curl --fail http://127.0.0.1:8090/api/info`.
Не запускайте локальную копию с тем же реальным токеном одновременно с сервером.

При откате остановите сервис и восстановите прежние JAR, конфигурацию и
сохранённую базу вместе: новая версия расширяет схему H2. Тег релиза — `v2.0.0`.
